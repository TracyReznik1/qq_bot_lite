# 可配置 qqbot 身份与 ATRI 分离设计

## 背景

项目已经通过 `BOT_NAME` 和 `BOT_PERSONA` 暴露了部分身份配置，但默认值、系统提示词、搜索失败提示、启动脚本、数据目录、回调请求头、网络 User-Agent 和 README 中仍存在 ATRI 硬编码。系统提示词还固定追加“温柔、日系、治愈、偶尔玩梗”等特点，使 `BOT_PERSONA` 不能成为完整的人设来源。

本次变更将 ATRI 从产品身份中分离，以 `qqbot` 作为默认机器人名称，并让名称与人设仅通过 `.env` 配置。每次大模型生成回复时都必须参考当前身份与设定。现有聊天、网页搜索、图片理解、历史和全部记忆能力保持不变。

## 目标

1. 默认机器人名称为 `qqbot`，默认人设为自然、友好、简洁、可靠的通用 QQ 聊天助手。
2. `BOT_NAME` 和 `BOT_PERSONA` 是机器人身份的唯一配置来源；配置在进程启动时读取，重启后生效。
3. 每次大模型调用都收到包含当前名称和完整人设的 system prompt，包括普通聊天、工具调用前的判断、自动搜索后的总结和 `/search` 回复生成。
4. 删除用户可见内容和正常运行标识中的 ATRI 名称。
5. 默认数据目录改为 `qqbot_data/`，启动时安全合并旧 `atri_data/`，成功后保留带时间戳的旧目录备份。
6. 新回调请求头为 `X-QQBOT-Callback-Secret`，同时兼容旧 `X-ATRI-Callback-Secret`，避免现有 OneBot 配置立即中断。
7. 只对现有 `.env` 做身份和数据目录所需的最小修改，不改动密钥、代理、管理员等其他配置。

## 非目标

- 不增加聊天命令来动态修改身份。
- 不增加网页管理界面、JSON 人设文件或数据库配置。
- 不允许记忆、用户消息或搜索结果修改身份配置。
- 不改变聊天、搜索、图片输入、历史或记忆的产品范围。
- 不将固定语气、称呼或风格拆成更多配置项。
- 不立即移除旧回调请求头兼容。

## 配置设计

### 唯一身份来源

`Config` 保留两个字段：

- `bot_name`：读取 `BOT_NAME`，去除首尾空白；缺失、空字符串或纯空白时使用 `qqbot`。
- `bot_persona`：读取 `BOT_PERSONA`，去除首尾空白；缺失、空字符串或纯空白时使用通用默认人设。

默认人设不重复名称，避免用户只修改 `BOT_NAME` 后出现名称冲突。默认文本为：

> 你是一个自然、友好、简洁、可靠的 QQ 聊天助手。

`.env.example` 明确列出：

```env
BOT_NAME=qqbot
BOT_PERSONA=你是一个自然、友好、简洁、可靠的 QQ 聊天助手。
```

### 现有 `.env` 的最小修改

实施时允许修改未提交的 `.env`，但只处理以下键：

1. `BOT_NAME` 缺失时添加 `qqbot`；值为 `ATRI`（忽略首尾空白和大小写）时替换为 `qqbot`；其他非空自定义值保持不变。
2. `BOT_PERSONA` 缺失时添加通用默认人设；值等于当前项目的 ATRI 默认人设时替换；其他非空自定义值保持不变。
3. `DATA_DIR` 明确等于 `atri_data` 时改为 `qqbot_data`；缺失时不强制添加，由代码默认值生效；其他自定义路径保持不变。
4. 不读取、输出或重写其他键的值，不调整原有 API Key、代理、管理员 QQ、模型或 OneBot 配置。
5. `.env` 继续由 Git 忽略，不进入提交。

## 提示词与模型调用

### 身份段

`build_system_prompt()` 每次调用时从 `config.bot_name` 和 `config.bot_persona` 构建 `[Character]` 段：

```text
[Character]
你扮演 <BOT_NAME>。
角色设定：<BOT_PERSONA>
```

删除固定的“温柔、日系、治愈、偶尔玩梗”列表。保留现有优先级规则：能力边界和安全规则高于角色人格；身份只影响模型回复的语气、称呼和表达，不得修改命令、工具或安全边界。

### 每次模型调用的覆盖

`generate_reply()` 在每次用户回复流程开始时重新构建 system prompt，并把它作为消息列表第一项。该消息列表用于：

1. 普通聊天的首次模型调用。
2. 模型判断是否调用 `search_web` 的调用。
3. 工具结果加入后的后续调用和最终总结调用。
4. 带 `tool_context` 的 `/search` 生成调用。
5. 带图片的多模态聊天调用。

因此，同一回复流程内的所有模型调用都包含同一份当前身份。固定命令回复（如 `/help`、`/remember`、`/reset`）不是大模型生成，不要求模仿人设；其中展示机器人名称的位置使用 `config.bot_name`。

删除 `/search` 搜索失败上下文里的“按 ATRI 的角色设定回答”，改成不绑定名称的“按当前角色设定回答”。

## ATRI 标识清理

以下用户可见或正常运行标识改为 `qqbot` 或配置值：

- README 标题、启动说明、监听说明、群聊示例、项目结构和数据目录说明。
- `启动ATRI.bat` 重命名为 `启动qqbot.bat`，安装完成提示使用 qqbot。
- 默认 `BOT_NAME`、默认 `BOT_PERSONA` 和默认 `DATA_DIR`。
- URL 抓取 User-Agent 改为 `qqbot-url-fetch/1.0`。
- 搜索失败提示中的 ATRI 名称。
- 新回调头改为 `X-QQBOT-Callback-Secret`。

源码中只允许两类必要的 ATRI 遗留引用：

1. 旧数据目录 `atri_data` 的迁移逻辑和测试。
2. 旧回调头 `X-ATRI-Callback-Secret` 的兼容逻辑和测试。

README 和 `/help` 不宣传旧名称或旧回调头。日志在收到旧回调头时可以记录不含密钥值的弃用提示。

## 回调鉴权

当 `CALLBACK_SECRET` 未配置时，行为保持不变，回调无需密钥。

配置密钥时，按以下方式授权：

1. `Authorization: Bearer <secret>`。
2. `X-QQBOT-Callback-Secret: <secret>`。
3. 兼容的 `X-ATRI-Callback-Secret: <secret>`。

任一方式通过恒定时间比较即授权。新请求头优先读取；旧请求头仅作为兼容入口，不出现在正常用户文档中。

## 数据目录迁移

### 触发时机

默认 `config.data_dir` 改为 `qqbot_data/`。迁移在 `startup()` 中执行，并位于现有 `migrate_legacy_memory_files()` 之前。迁移函数接收明确的源目录、目标目录、历史上限和记忆上限，避免在测试中依赖真实工作区。

正常启动入口必须先完成 `startup()`，再接受消息。除 `run()` 启动时调用外，OneBot 事件入口也要经过同一个幂等的启动守卫，保证 WSGI 等导入式运行方式不会跳过迁移。迁移函数不得在模块导入时修改数据。

### 识别的数据

- `memories/*.json`：结构为 `{ "facts": [...] }`。
- `history/*.json`：结构为 `{ "messages": [...] }`。
- 其他文件和子目录：作为未知数据处理。

### 合并规则

当只有 `atri_data/` 存在时，也执行同一套合并流程，不直接原地使用旧目录。

当新旧目录同时存在时：

- 同名记忆文件：按“旧事实、新事实”顺序拼接，去除重复的非空字符串，最后保留 `MEMORY_LIMIT` 条。
- 同名历史文件：按“旧消息、新消息”顺序拼接，只保留包含 `role` 和 `content` 的字典，最后保留 `HISTORY_TURNS * 2` 条。
- 只在旧目录存在的文件复制到新目录。
- 同名未知文件使用新目录版本；旧版本仍保留在迁移后的完整备份中。

### 安全替换与备份

迁移采用同一父目录下的临时工作目录：

1. 将现有 `qqbot_data/` 完整复制到临时目录；目标不存在时创建空临时目录。
2. 在临时目录合并旧数据，不修改源目录和正式目标。
3. 重新读取并校验所有本次写入的已知 JSON 文件。
4. 将现有目标临时改名为回滚目录，再把合并完成的临时目录改名为 `qqbot_data/`。
5. 将 `atri_data/` 改名为 `atri_data.backup-YYYYMMDD-HHMMSS`；重名时追加递增序号。
6. 正式目标替换成功后删除临时回滚目录。

如果任何读取、复制、校验或改名失败：

- 尽力恢复替换前的 `qqbot_data/`。
- 保留 `atri_data/` 和所有未完成的恢复材料。
- 记录不含聊天、记忆或密钥内容的错误日志。
- 抛出启动错误并阻止服务开始接收消息。

迁移成功后源目录已改名，不会在下次启动重复合并。

若 `DATA_DIR` 被配置为其他自定义路径，不自动把 `atri_data/` 合并到该路径；自动迁移只针对默认路径或明确的 `qqbot_data` 目标，避免把旧数据意外写入用户选择的外部目录。

## 错误处理与日志

- 身份配置为空时使用默认值，不阻止启动。
- 数据迁移失败是启动阻塞错误，不允许带着部分合并结果运行。
- 旧回调头鉴权成功时只记录弃用事件，不记录请求头值。
- 迁移日志只记录源目录、目标目录、文件计数、成功或失败状态，不记录 JSON 内容。
- 现有聊天、搜索、图片、模型回退和用户错误提示保持不变。

## 测试设计

### 身份配置

- 无环境变量时使用 `qqbot` 和通用默认人设。
- `BOT_NAME`、`BOT_PERSONA` 自定义值经去空白后生效。
- 空字符串和纯空白回退默认值。
- 默认人设不包含固定名称，修改名称不会产生身份冲突。

### 提示词和回复路径

- system prompt 包含当前名称和完整人设。
- system prompt 不再固定包含“温柔、日系、治愈、偶尔玩梗”。
- 普通聊天的每次 `llm.chat()` 调用都带身份 system message。
- 自动搜索工具调用后的总结仍带身份。
- `/search` 回复生成带身份，失败上下文不含 ATRI。
- 多模态图片聊天保持同样身份注入。

### 数据迁移

- 只有旧目录时迁移并生成备份。
- 新旧目录同时存在时按规则合并记忆和历史。
- 记忆去重并按上限截断。
- 历史按旧后新顺序合并并按上限截断。
- 未知文件缺失时复制、冲突时保留新版本。
- 备份目录重名时不覆盖。
- 无旧目录时不改动新目录。
- 模拟复制、写入、校验或改名失败时恢复目标并保留源目录。
- 成功迁移后再次启动不会重复合并。

### 品牌与兼容

- 新旧回调请求头和 Authorization 均可通过鉴权，错误密钥被拒绝。
- README、帮助、启动脚本、默认配置和 User-Agent 使用 qqbot。
- 残留扫描只允许迁移与旧请求头兼容位置出现 ATRI。
- `.env.example` 包含身份选项。

### 回归验证

- 运行全部单元测试。
- 对 `src/` 和 `tests/` 执行 AST 与编译检查。
- 执行 `git diff --check`。
- 确认 `.env` 未进入 Git 差异，且其中非目标键未改变。

## 验收标准

1. 未配置身份时，机器人以 `qqbot` 和通用助手人设回复。
2. 修改 `.env` 的 `BOT_NAME`、`BOT_PERSONA` 并重启后，每次模型调用都包含新身份。
3. 系统提示词不再追加固定 ATRI 风格特点。
4. 用户可见内容、启动脚本和正常网络标识不再使用 ATRI。
5. 新旧回调请求头都能鉴权，文档只推荐新请求头。
6. 旧数据自动合并到 `qqbot_data/`，冲突遵循“旧在前、新在后”，旧目录变为时间戳备份。
7. 迁移失败不会覆盖或删除旧数据，也不会启动服务。
8. `.env` 只发生已批准的身份和数据目录修改，其他值保持字节级不变。
9. 现有聊天、搜索、图片、历史、`/remember`、`/globalremember`、`/help` 和 `/reset` 测试继续通过。

## 已知限制

- 身份配置只在进程启动时读取，修改 `.env` 后需要重启。
- 旧回调头暂时保留，因此源码和测试中仍会出现一类 ATRI 兼容标识。
- 历史文件没有时间戳，双目录冲突时只能按已确认的“旧目录内容在前、新目录内容在后”规则合并。
- 未知同名文件无法安全语义合并，使用新版本并依靠完整旧目录备份保留旧版本。
