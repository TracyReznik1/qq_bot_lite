# qqbot_lite 结构化自适应记忆与角色设定设计

日期：2026-07-26
状态：已确认，待实现计划

## 1. 背景

当前记忆系统把内容保存为按文件分组的裸字符串列表，并在生成提示词时一次性拼接会话、个人和全局记忆。旧数据没有发言者、信息主体、来源、时间、置信度或冲突关系。

因此，全局记忆中的“我是夏目安安”可能被错误地用于回答另一个用户的“我是谁”。系统也无法可靠表达“谁说了什么”、同一个人后来是否修改了说法，以及不同人的冲突观点。

本设计把记忆改为本地 SQLite 中的结构化主张账本。可见范围与信息主体严格分离，所有普通私聊消息和群内所有 @Bot 的消息都有自动学习机会，但只有经过提取、校验和隐私策略的长期有用信息才会进入有效记忆。

用户已要求删除活动目录中的旧记忆。`qqbot_data/memories/` 中原有的一条旧全局裸文本已删除，因此新系统从空记忆库开始，不迁移旧 JSON 内容。

## 2. 核心目标

1. 让 Bot 明白每个 QQ 是谁，不把一个人的身份或偏好套用给其他人。
2. 分离私聊、每个群和全局记忆；同一 QQ 在不同作用域可以有不同资料。
3. 自动从自然对话学习、确认、修正、撤回和归档信息，而不是只会追加文本。
4. 记录发言者、信息主体、来源、时间、置信度和冲突关系。
5. 保留不同人的不同观点，让模型按证据和置信度决定如何使用。
6. 在多人并发和同一用户连续发言时保持回复顺序、写入安全和任务可恢复。
7. 所有正常用户交流遵守独立角色设定文件；技术故障优先准确说明真实原因。
8. 保留 `/remember`、`/globalremember`，增加最小必要的查看和删除能力。

## 3. 非目标

- 不建立外部托管记忆服务或独立图数据库。
- 首版不依赖向量数据库；使用 SQLite 结构化查询和 FTS5。
- 不把聊天记录全文复制为长期记忆。
- 不把网页搜索结果自动固化为长期公共事实。
- 不允许角色文件改变权限、隐私、安全、工具或事实规则。
- 不迁移或继续读取旧 JSON 记忆。

## 4. 方案选择

采用本地 SQLite 结构化主张账本。

未选择 Graphiti/Zep 的原因是其时态知识图谱能力虽强，但会引入额外数据库、嵌入和部署复杂度。未选择 Mem0/Letta 作为主存储，是因为本项目需要精确实现 QQ、群、私聊和全局的自定义权限语义，并保持本地、轻量和可审计。

SQLite 方案保留清晰接口，未来可以在不改变上层权限模型的前提下增加嵌入检索或图关系适配器。

## 5. 作用域与隐私模型

### 5.1 基本原则

“谁能看到”与“这条信息描述谁”是两个独立字段。

`/globalremember 我是夏目安安，我喜欢跑步` 由 QQ A 执行时，应形成两条全局可见主张：

- 发言者 A，主体 A，姓名为夏目安安。
- 发言者 A，主体 A，喜欢跑步。

全局表示所有会话都可以检索该主张，不表示所有用户都叫夏目安安或喜欢跑步。

### 5.2 作用域

| 作用域 | 标识 | 主要内容 | 可见范围 |
| --- | --- | --- | --- |
| 私聊个人 | `private:<qq>` | 当前 QQ 在私聊中的身份、偏好、经历 | 仅该 QQ 的私聊 |
| 群 | `group:<group_id>` | 当前群成员资料、观点、事件、共同知识 | 仅当前群 |
| 全局 | `global` | 管理员明确提升的共享知识 | 所有会话 |
| Bot | `bot` | Bot 名称、身份和角色设定 | 所有会话，来源为角色文件 |

同一 QQ 在私聊、群 1、群 2 中可以有不同称呼、偏好或身份描述。各作用域的记录不自动合并、复制或互相覆盖。

### 5.3 私聊检索边界

私聊回答的主要来源是：

1. 当前 QQ 的私聊记忆。
2. 全局记忆。
3. 当前 QQ 在其群聊中的本人资料，只在私聊缺少对应信息时作为低优先级临时参考。

第三项只允许参考关于当前 QQ 本人的资料，不读取其他成员资料、群体共同信息或其他主体的群内观点。回退不会复制数据、提高置信度或改变原作用域。

### 5.4 群聊检索边界

群聊回答的主要来源是：

1. 当前群记忆。
2. 全局记忆。
3. 当前发言者的私聊记忆，仅用于称呼和个性化表达。

当前发言者的私聊记忆不能成为在群里公开介绍其身份、关系、经历或敏感资料的证据。其他成员询问某人时，只能使用当前群和全局中允许访问的内容。群 A 的内容不得传播到群 B。

### 5.5 权限硬过滤

权限过滤必须在语义检索和模型调用之前完成。禁止把全部记忆交给模型后要求模型自行保密。任何相关性、置信度、搜索结果或角色设定都不能突破作用域过滤。

## 6. 实体与代词解析

- “我、我的”指当前消息作者。
- 面向 Bot 的“你”指 Bot 实体。
- QQ @ 提及指精确的被提及 QQ。
- 回复或引用消息优先绑定被回复消息作者。
- 名称和别名先在当前群解析，再查找全局明确身份。
- 第三人称代词只有在近期上下文存在唯一候选主体时才解析。
- 无法唯一解析的名称或代词不生成有效主张。
- 疑问句不转化为事实。
- 区分否定、推测、假设、转述、玩笑、反讽和撤回。
- 用户关于 Bot 的陈述可以保存为该用户的观点或偏好，但不能覆盖 `config/persona.md`。

## 7. 结构化数据模型

核心记录为 `MemoryClaim`，至少包含：

- `id`
- `scope_type`：`private`、`group`、`global` 或 `bot`
- `scope_id`
- `speaker_qq`
- `subject_type`
- `subject_id`
- `predicate`
- `value`
- `memory_type`：身份、称呼、偏好、观点、事件、计划、关系、一般事实等
- `modality`：确定陈述、推测、转述、否定等
- `source_kind`：普通消息、命令、图片辅助等
- `source_message_id`
- `source_excerpt`
- `extraction_confidence`
- `attribution_confidence`
- `truth_confidence`
- `status`：`active`、`disputed`、`superseded`、`retracted`、`archived`
- `created_at`
- `valid_from`
- `valid_to`
- `last_confirmed_at`
- `dedupe_key`

关系表记录主张之间的 `supports`、`contradicts`、`supersedes` 和 `retracts`。证据表允许同一主张关联多个独立来源。后台任务表保存消息学习任务、重试次数、状态和错误类型。

归因置信度与事实置信度必须分开：

- 显式命令能高度确认“谁要求保存这条内容”。
- 它不能单独证明内容是客观事实。
- 不同人对同一事物的观点可以同时具有高归因置信度，而没有唯一客观结论。

提取置信度使用可解释等级，不依赖模型随意给出的精确小数：

- `low`：主体、作用域、陈述性质或关键字段无法可靠确定，不写入主张。
- `medium`：结构完整且归因明确，但内容本身带有推测、转述或不确定性；可以保存为低事实置信度主张，不能作为确定事实。
- `high`：结构完整、主体明确且属于直接陈述；可以进入正常冲突与更新流程，但仍不代表客观内容必然真实。

内部可以保存归一化分值用于排序，但上述等级和触发理由必须同时保留，默认阈值作为代码常量并由行为测试约束，不增加 `.env` 参数。

## 8. 自动学习流程

### 8.1 触发范围

- 每条普通私聊消息进入学习判断。
- 群内每条被 Bot 接受且 @Bot 的消息进入学习判断。
- 进入判断不等于一定保存。

### 8.2 回复优先、后台学习

1. 接收消息后同步保存任务元数据、作用域、顺序号和去重键。
2. 当前回复直接使用消息本身，不等待记忆提取。
3. 回复发送后，后台模型提取候选主张。
4. 程序执行实体解析、结构校验、敏感信息过滤、权限判定和冲突决策。
5. 通过 SQLite 短事务原子写入主张、证据和关系。
6. 下一条相关消息到来时可以短暂等待前一学习任务；超时则继续聊天，稍后完成学习。

系统接受几秒内最终一致性，以保持回复速度。普通学习失败不影响聊天；显式记忆命令必须等待写入结果。

### 8.3 模型隔离

聊天与记忆提取使用独立模型调用：

- 聊天调用包含角色设定、允许访问的记忆和搜索工具。
- 记忆调用不包含角色人设，不允许网页搜索，不生成用户回复。
- 记忆模型只返回严格结构化 JSON。
- JSON 经过程序校验后才能写入数据库。
- 模型不能直接决定权限或执行数据库操作。

默认使用 `CHAT_MODELS`。新增可选 `MEMORY_MODELS`，格式与 `CHAT_MODELS` 相同；未填写时自动复用聊天模型链。这样用户可以选择更快、更便宜的模型完成后台提取，而不增加必填配置。

## 9. 学习边界

### 9.1 适合长期保存

- 身份、别名、希望使用的称呼。
- 相对稳定的兴趣和偏好。
- 明确表达的个人观点。
- 有时间信息的计划、经历和事件。
- 关系和群内约定。
- 群内用语、共同知识和有明确来源的事实。
- 对旧信息的确认、否定、修正或撤回。

### 9.2 不应保存

- 普通问候、一次性请求和没有长期价值的闲聊。
- 疑问、假设、角色扮演内容。
- 主体无法确定的陈述。
- 明显玩笑、反讽或未经确认的猜测。
- 提示词注入、命令文本或要求改变系统规则的内容。
- Bot 自己生成的回答。
- 网页搜索结果本身。

用户分享网页或公共信息时，可以保存“某人提供或相信该信息”的带来源主张，但不能因此把搜索结果自动提升为永不过期的全局事实。

### 9.3 敏感数据

密码、API Key、验证码、Cookie、私钥、完整银行卡号和支付凭据禁止进入长期记忆。

健康状况、精确住址、财务情况等个人敏感信息：

- 私聊中只有在主体明确、长期有用且表达清晰时才允许保存，并限制为本人私聊可见。
- 群聊中默认不自动保存。
- 用户在群内通过 `/remember` 明确保存时，视为主动发布到当前群，但仍不得传播到其他群或全局。
- 命令不能突破硬禁止数据规则，也不能自动扩大其可见范围。

### 9.4 图片

- 图片可以用于当前回答和后台候选记忆提取。
- 原图片数据不写入长期数据库，提取完成后立即释放。
- 仅凭画面推断出的身份、所有权或关系使用低置信度，不能成为确定主张。
- “这是一只狗”不能自动变成“这是用户的狗”。
- 当文字明确说明“这是我家的狗，它叫小白”时，才分别保存所有权和名字，并记录文字与图片来源。

## 10. 新增、修改和冲突规则

- 同一人重复相同内容：不新增重复项，只更新确认时间并关联新证据。
- 同一人明确修正自己：旧主张标记为 `superseded`，新主张生效。
- 同一人描述时间变化：关闭旧主张有效期，保存新主张，不改写历史。
- 同一人撤回自己的陈述：旧主张标记为 `retracted`。
- 不同人提出冲突观点：两条都保留并标记争议。
- 一个人不能覆盖另一个人的观点或陈述。
- 提取置信度过低：候选在写入前丢弃。
- 已保存主张后来置信度过低：归档并停止注入聊天上下文，不自动立即物理删除。
- 独立来源可以增加事实置信度；同一发言者重复陈述不视为独立证据。
- 更新规则根据主体、谓词、作用域、发言者、时间和语义共同判断，不能只用文本相似度。

## 11. 时间与生命周期

- 身份、姓名和稳定关系不因时间自动失效，只由明确修正、撤回或可靠冲突改变。
- 首选称呼不随时间衰减。
- 兴趣和偏好可以因近期确认获得排序加成，但始终保留最低检索优先级，不会仅因时间久远接近不可检索。
- 同一人的观点变化保留历史时间线。
- 计划和临时状态按有效期过期，不再作为当前状态。
- 已发生事件作为带时间的经历保留。
- 公共事实记录获知时间；时效性问题优先网页搜索。
- 传闻和转述保留“谁转述了什么”，事实置信度较低。

只保存支持主张所需的最短原文摘录。已取代、撤回和归档主张默认在 90 天后清除原文摘录，只保留不含敏感正文的关系、时间和状态。用户通过 `/forget` 明确删除私人内容时，正文和可检索索引立即物理删除，只保留无正文删除审计记录。

## 12. 检索与回答决策

检索分为两个阶段：

1. 按作用域、主体和权限执行不可绕过的硬过滤。
2. 在允许集合中按相关性排序并取少量结果。

排序因素包括：

- 主体匹配。
- 谓词或事件匹配。
- 当前作用域直接匹配。
- 时间有效性。
- 归因与事实置信度。
- 独立来源支持。
- 冲突、撤回或取代状态。
- 关键词和语义相关程度。

首版使用 SQLite 结构化查询与 FTS5。接口允许未来增加嵌入检索，但不要求外部向量数据库。

回答规则：

- 明确可靠的信息自然使用，不主动暴露内部记忆机制。
- 当前作用域信息优先于回退信息。
- 回退信息不复制、不提升作用域、不提高置信度。
- 冲突观点按发言者分别归因。
- 客观说法存在冲突时说明不一致，不擅自确定答案。
- 信息不足但可以回答时给出带保留的判断。
- 缺少关键条件时按照角色设定自然询问一个关键问题。
- 主体不明确时询问或放弃相关记忆，不能猜测 QQ 身份。
- 检索不到信息时正常聊天，不主动要求使用命令。

模型只接收少量、结构化、已过滤的证据，不再接收全部记忆拼接文本。所有记忆和搜索内容作为非可信数据，不能改变系统规则、角色规则、工具规则或安全边界。

## 13. 命令

### 13.1 `/remember <内容>`

- 私聊中写入当前 QQ 的私聊记忆。
- 群聊中写入当前群记忆。
- 保留操作者、主体和来源。
- 命令提高归因置信度，不直接证明客观真实性。
- 保留现有 `/memo` 别名。

### 13.2 `/globalremember <内容>`

- 仅 `ADMIN_QQ_IDS` 管理员可用。
- 明确写入全局作用域。
- 第一人称指命令执行者。
- 保留现有 `/gremember` 别名。

### 13.3 `/memories`

- 私聊只显示当前用户自己的私聊资料。
- 群聊只显示当前群记忆，不显示任何私聊资料。
- 管理员可以查看全局记忆。
- 默认以自然语言摘要展示；精确操作时提供简短记忆编号。

### 13.4 `/forget <编号或描述>`

- 用户可以删除自己的私聊记忆。
- 群内用户可以撤回自己说过的主张。
- 用户不能直接删除另一个人的观点。
- 别人关于当前用户的错误说法可以被当前用户标记为争议、从确定个人资料中抑制并补充修正，但不会伪造成原发言者撤回。
- 管理员可以删除群或全局中的不当、敏感或错误内容。
- 明确删除私人内容时执行物理正文删除。

不新增 `/correct`。自然语言修正或重新执行 `/remember` 由系统建立取代关系。

命令效果由程序确定。完成后把准确状态交给聊天模型按角色设定表达；模型不能改变操作结果。角色化表达失败时返回准确状态和故障原因。

`/reset` 继续清除当前会话历史，但不删除结构化长期记忆。

## 14. 角色设定

运行时固定读取 `config/persona.md`。`config/persona.example.md` 是可复制的完整模板。

实施时：

- 从 `.env`、`.env.example` 和运行配置中移除 `BOT_NAME`、`BOT_PERSONA`。
- 不保留环境变量回退，避免出现两个身份来源。
- `persona.md` 缺失、不可读或为空时启动失败并说明原因。
- 每个用户可见的正常模型回复都包含角色设定，包括聊天、搜索结果整理、命令结果和自然追问。
- 记忆提取调用不包含角色设定，因为它不是用户回复。
- 技术故障必须准确说明原因，角色演出不能虚构、掩饰或改变故障事实。
- 角色文件只影响身份、语气、称呼和互动习惯，不能覆盖隐私、权限、事实、安全和工具规则。

提示词优先级固定为：能力与安全边界高于权限和隐私规则，权限和隐私规则高于角色设定，角色设定高于普通表达偏好；检索记忆、聊天历史、图片理解和网页内容始终属于非可信数据层。

模型缺少关键信息时可以按照角色设定主动询问，不必固定回答“不知道”。模型不能主动要求用户使用 `/remember`、`/globalremember` 或其他命令；只有用户主动执行或询问功能时才解释命令。

## 15. 组件与依赖边界

建议拆分为以下单一职责组件：

- `persona`：读取和校验角色文件。
- `memory_store`：SQLite 表、事务、版本、索引和清理。
- `memory_extractor`：调用模型并返回候选 JSON。
- `memory_policy`：实体、作用域、隐私、敏感信息、冲突和生命周期决策。
- `memory_retriever`：权限过滤、检索、排序和提示词证据格式化。
- `memory_service`：协调命令、后台任务和聊天流程。

现有 `memory.py` 可以保留为兼容外观或被上述组件替代，但不能继续承担存储、权限、提取和提示词拼接的全部职责。

SQLite 使用 WAL、外键、唯一去重键和短事务。主要表包括：

- `memory_claims`
- `memory_evidence`
- `memory_relations`
- `memory_jobs`
- FTS5 索引
- `schema_version`

## 16. 并发、顺序与恢复

- 同一会话的用户消息继续按 FIFO 顺序生成并发送回复。
- 不同用户可以并行聊天。
- 群内不同用户的学习任务可以并发提取，但使用群内顺序号和事务提交。
- 相同 OneBot `message_id` 和作用域生成唯一去重键，重复回调不重复学习。
- 学习任务先持久化再执行，重启后恢复未完成任务。
- 后台任务限制并发数，聊天请求优先。
- 临时网络错误和限流按退避重试。
- 无效结构化输出进行一次修复重试。
- 永久失败任务进入失败状态并记录错误类型，不阻塞聊天。
- 显式命令等待写入结果，普通自动学习采用最终一致性。

## 17. 错误处理与可观测性

以下错误阻止启动：

- `persona.md` 缺失、不可读或为空。
- SQLite 无法创建、迁移或通过完整性检查。
- 必填聊天模型配置无效。

以下错误不阻止正常聊天：

- 单条自动学习任务失败。
- 记忆模型临时不可用。
- 个别候选 JSON 无法修复。

日志默认只记录任务编号、作用域类型、状态、耗时、重试次数和错误类型。不得输出私密记忆正文、完整消息、图片数据、密钥或支付信息。

命令失败必须准确告诉用户没有完成操作。普通后台学习失败不主动打断当前聊天，但必须保留可诊断状态。

## 18. 旧数据和启动行为

- 新系统创建空 SQLite 记忆库。
- 删除并停止调用现有旧 JSON 记忆迁移流程。
- 运行时不得读取 `qqbot_data/memories/*.json`。
- 已存在的 `atri_data.backup-*` 归档保持不变，但不参与运行。
- 数据库结构升级通过版本化事务迁移，不使用旧裸文本转换。

## 19. 验收标准

必须覆盖以下自动测试和集成场景：

1. A 的私聊身份不会用于回答 B 的“我是谁”。
2. A 在私聊、群 1、群 2 可以拥有不同资料。
3. 群 1 信息不会传播到群 2。
4. 群内只有限使用当前发言者私聊资料进行个性化。
5. `/globalremember 我是夏目安安` 正确归属执行者。
6. 不同人的冲突观点同时保留并分别归因。
7. 同一人修正自己时建立取代关系，不无限追加。
8. 长时间未确认的称呼和偏好仍可检索。
9. 疑问、玩笑、转述、否定和不明确代词不被误存为确定事实。
10. 图片不能单独证明人物身份、物品所有权或关系。
11. 密码、密钥、验证码等不进入数据库或日志。
12. `/remember` 在私聊和群聊写入不同作用域。
13. `/memories`、`/forget` 遵守查看与删除权限。
14. 重复 OneBot 回调不重复学习。
15. 同一用户连续消息的回复和学习顺序稳定。
16. 多用户并发和群记忆并发写入不丢失或覆盖数据。
17. 记忆模型限流、无效 JSON 和程序重启后任务可重试恢复，聊天仍可继续。
18. `persona.md` 缺失或为空时启动失败并说明原因。
19. 所有正常用户回复保持角色设定，故障说明保持准确。
20. 记忆和网页内容不能修改系统规则、权限或角色边界。
21. 旧 JSON 记忆不再被运行程序读取。

## 20. 参考依据

- [Mem0 Memory Update](https://docs.mem0.ai/core-concepts/memory-operations/update)：记忆更新而非只追加。
- [CoALA](https://arxiv.org/abs/2309.02427)：语言智能体的模块化记忆架构。
- [Generative Agents](https://arxiv.org/abs/2304.03442)：经历、反思和动态检索。
- [LongMemEval](https://arxiv.org/abs/2410.10813)：多会话推理、时间推理、知识更新和拒答评测。
- [Zep: A Temporal Knowledge Graph Architecture for Agent Memory](https://arxiv.org/abs/2501.13956)：时态事实和历史关系。
- [Graphiti](https://github.com/getzep/graphiti)：带来源、有效期和混合检索的动态知识图谱。
- [LoCoMo](https://arxiv.org/abs/2402.17753)：长期对话记忆评测。
