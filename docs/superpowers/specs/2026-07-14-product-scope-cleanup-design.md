# qqbot_lite 产品范围精简设计

## 目标

将 qqbot_lite 收敛为只提供聊天和网页搜索的 QQ 机器人，同时保留聊天所需的上下文管理、历史记录和记忆能力。聊天允许用户发送图片，由模型按自身能力理解并回答；图片属于聊天输入，不扩展为图片生成、编辑或主动发送能力。删除与图片生成、视频、OpenAI 媒体管线、ComfyUI 和独立 URL 直读有关的残留入口、配置与不可达代码。

## 保留范围

- 普通聊天。
- 用户发送的图片或“图片 + 文字”聊天输入。
- 普通聊天中的自动网页搜索工具调用。
- `/search <关键词>` 显式网页搜索。
- `/help` 和 `/reset`。
- `/remember`、`/globalremember` 和完整记忆模块。
- 聊天历史持久化。
- Gemini/DeepSeek 模型回退。
- OneBot 文本消息收发、群聊 `@` 检查、消息去重和会话队列。
- 网页搜索内部对搜索结果页面的正文抓取、安全校验和证据整理。

## 删除范围

- `/search <URL>` 直接读取指定网页的特殊分支。
- `OPENAI_API_KEY` 预留配置。
- `VIDEO_*` 配置。
- 图片生成相关的 `IMAGE_*` 配置。
- `COMFYUI_*` 配置。
- `OneBotClient.send_image()` 及其仅为图片发送存在的依赖和注释。
- 与上述能力相关的过期说明或容易造成误解的文档表述。

## 不在本次范围内

- 不删除记忆功能或聊天历史。
- 不删除 `url_fetch_service.py`，因为网页搜索需要它读取搜索结果页面。
- 不重命名或重构搜索抓取模块。
- 不提供图片生成、图片编辑或机器人主动发送图片。
- 不改变搜索来源排序、相关性判断、模型回退或 OneBot 文本发送逻辑。
- 不修改 `.env`、现有聊天历史或记忆数据。
- 不新增第三方运行依赖。

## 架构与数据流

普通聊天继续由 `src.chat.chat_service` 暴露唯一工具 `search_web`。显式 `/search` 命令只把输入作为搜索关键词交给 `search_service.search()`；不再检测 URL，也不直接调用 `fetch_url()`。

`search_service` 仍可在搜索完成后调用 `url_fetch_service.fetch_url()`，读取有限数量的结果页正文。这属于网页搜索内部证据增强，不是独立的用户功能。

OneBot 客户端只保留文本消息发送。图片、视频和媒体生成没有路由、命令、工具或配置入口。

### 图片聊天输入

消息入口优先从 OneBot 结构化消息段读取 `text` 和 `image`；在结构化图片 URL 不可用时，兼容从 CQ 图片码提取 URL。纯图片和“图片 + 文字”都按普通聊天处理，群聊仍必须满足现有 `@` 规则。

图片在内存中读取并转换为 base64 data URL，再以 OpenAI 兼容的多模态 `content` 列表传给模型。固定限制为每条消息最多 4 张图片、每张最多 5 MiB，只接受 JPEG、PNG、WebP 和 GIF。下载失败、内容类型不匹配或超限时，不把无效数据传给模型，并向用户返回明确说明。

模型客户端继续透传 OpenAI 兼容消息。模型若不支持图片并返回错误，现有回退链继续尝试下一个模型；若全部模型失败，返回“当前模型无法识别该图片”，不把它包装成普通配置错误。

图片二进制、base64 和临时 URL 不写入聊天历史。历史中的用户消息只保存 `[图片]` 占位符和附带文字，后续轮次可知道先前存在图片，但不会重复上传旧图片。

- 修改 `src/services/llm_client.py`：所有模型无法处理图片时返回图片识别专用错误。
- 修改 `README.md`：明确 `/search` 是关键词搜索，搜索引擎内部可读取结果页；用户可发送图片供模型识别，但不提供独立 URL 直读、图片生成或主动发图。
- 修改 `src/commands/help.py` 和 `src/chat/prompt.py`：使帮助文本和能力边界与实际产品范围一致。

- 新增 `tests/` 下的标准库 `unittest` 测试。

## 错误处理

搜索失败仍由搜索服务返回结构化状态，普通文本模型不可用仍由回退客户端统一报错，OneBot 文本发送仍记录异常。删除 URL 直读分支后，包含 URL 的 `/search` 输入按普通搜索词处理，其失败行为与其他搜索词一致。

图片输入错误分为三类：消息中没有可用图片 URL、图片读取或格式校验失败、全部模型无法识别。三类错误都返回面向用户的简短说明，不记录或持久化图片二进制。

## 测试策略

使用 Python 标准库 `unittest`，不增加依赖。

测试覆盖：

1. `/search` 对包含 URL 的输入仍调用网页搜索，而不调用独立 URL 读取。
2. `Config` 不再暴露 OpenAI、视频、图片和 ComfyUI 配置字段。
3. `OneBotClient` 不再暴露 `send_image()`。
4. `/remember`、`/globalremember`、`/help`、`/reset` 和 `/search` 仍注册。
5. 普通聊天仍只暴露 `search_web` 工具。
6. `search_service` 仍使用 `fetch_url()` 增强搜索结果正文。
7. 纯图片、图片加文字、群聊 `@ + 图片` 能被解析为聊天输入。
8. 合法图片会转换为多模态模型消息；超限或非图片内容会被拒绝。
9. 图片历史只保存 `[图片]` 占位符和文字，不包含 base64 或临时 URL。
10. 某个模型不支持图片时继续回退，全部模型失败时返回图片识别专用提示。

测试遵循红—绿流程：先在当前代码上运行并确认范围测试因残留能力存在而失败，再进行最小删除，最后运行全部测试、Python 语法检查和 Git 差异检查。

## 验收标准

- 产品可达能力只包含聊天（含图片输入理解）、网页搜索、聊天历史和记忆管理。
- 不存在 OpenAI 媒体、视频、图片生成或 ComfyUI 配置字段。
- 不存在 OneBot 图片发送方法。
- 用户可以发送最多 4 张、每张不超过 5 MiB 的 JPEG、PNG、WebP 或 GIF，由支持图片的模型识别并回答。
- 不支持图片的模型不会阻断后续模型回退；全部失败时返回明确提示。
- 历史文件不保存图片二进制、base64 或临时 URL。
- `/search <URL>` 不再直接抓取该 URL。
- 搜索内部结果页抓取仍正常保留。
- 记忆相关命令与模块不被删除。
- 文档和帮助文本与代码一致。
- 新增测试全部通过，Python 文件可解析。
